## Project

`@dpaskhin/unique` is a tiny TypeScript library (single source file) that generates unique values by
retrying a generator function until a non-duplicate result is produced, tracked via a `Set`-based store.

## Commands

```shell
npm run build            # bundle with tsup -> lib/ (cjs + esm + .d.ts)
npm test                 # run vitest once
npm run test-coverage    # vitest run --coverage (100% coverage threshold enforced, see vitest.config.ts)
npx vitest run src/test/unique.test.ts -t "should return unique values"   # run a single test
npm run type-test        # tsd type-level tests against src/test/types/index.test-d.ts
npm run lint             # tsc (type-check only, no emit)
npm run check-format     # prettier --check .
npm run format           # prettier --write .
npm run check-exports    # @arethetypeswrong/cli check on the packed package
npm run ci               # build + check-format + check-exports + lint + test-coverage + type-test (run before publishing)
```

There is no separate lint config (ESLint) — type-checking via `tsc` and Prettier formatting are the only static checks.

## Architecture

- All implementation lives in `src/main/index.ts` — a single file exporting `unique`, `uniqueFactory`, and
  `GLOBAL_STORE`.
- `uniqueFactory(fn, options)` is the core primitive: it wraps `fn` in a loop that calls it, stringifies the
  result (via `options.stringifier`, default `JSON.stringify`), and checks it against `options.store` (a `Set`)
  and an `exclude` list. It retries until a non-duplicate is found or `maxRetries`/`maxTime` is exceeded, then
  throws a `UniqueError`.
- `unique(fnOrValue, argsOrOptions?, options?)` is an overloaded convenience wrapper around `uniqueFactory`:
  - Called with a no-arg function, or a function + args array — delegates to `uniqueFactory` and invokes it once,
    defaulting to `GLOBAL_STORE` when no store is given.
  - Called with a plain (non-function) value — treated as a single-attempt uniqueness check (`maxRetries: 1`)
    against the store; throws if the value was already seen.
- `GLOBAL_STORE` is a module-level `Set` shared across the app when no custom `store` is passed; tests must call
  `GLOBAL_STORE.clear()` in `beforeEach` to avoid cross-test pollution (see `src/test/unique.test.ts`).
- Build output (`lib/`) is generated by tsup from `tsup.config.ts` and is committed as the publishable package
  content (`package.json` `files`/`exports`/`main`/`types` all point into `lib/`) — never hand-edit `lib/`.
- Type-level behavior (overload resolution, inferred return types) is verified separately via `tsd` in
  `src/test/types/index.test-d.ts`, distinct from the runtime tests in `src/test/unique.test.ts`.
- Releases are managed with Changesets (`.changeset/`); `npm run local-release` runs `changeset version && changeset publish`.
